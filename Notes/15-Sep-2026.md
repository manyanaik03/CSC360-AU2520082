### 1: Project Peer Review Actually Involves

- Instead of everyone working in isolation, each team presents their current project progress to the professor (and, indirectly, to classmates working on different projects) so feedback happens early rather than only at final submission.
- The point isn't just showing what's done — it's explaining the reasoning behind design choices, since a professor reviewing many different projects needs the "why" as much as the "what" to give useful feedback.
- Being asked to explain the project out loud is itself useful — gaps in the plan tend to surface the moment you have to justify a step to someone else, even before they say anything.

### 2: Walking Through the Project Pipeline

- The project was explained as a step-by-step pipeline rather than a finished feature list: JavaFX Application → Button + WebView → HTML Page → JavaScript/DOM Integration → DOM Modification → Dynamic Text/Color Changes.
- Presenting it this way made it clear which stages were already working (JavaFX app with WebView loading an HTML page) versus which were still ahead (the actual DOM modification and dynamic styling logic).
- WebView was explained as JavaFX's embedded browser — it's what makes "a browser inside a desktop app" possible in the first place, rather than needing a separate browser window.

### 3: Feedback on the WebView + DOM Approach

- The general direction (JavaFX button triggering changes inside an embedded web page) was accepted as a reasonable scope for the project — not overly simple, not unreasonably large.
- Feedback focused on making sure the DOM-modification step is demonstrated clearly — i.e. the "before vs after" change (text or color updating on click) needs to be visibly obvious, not just technically present in the code.
- The suggestion was to keep the demo simple and clearly visible rather than adding many DOM operations — one clean, working interaction is more convincing than several half-finished ones.

### 4: Where the Project Stands Right Now

- Completed so far: the JavaFX application shell, the WebView component, and it successfully loading an HTML page.
- Still pending: the actual JavaScript/DOM integration — connecting a JavaFX button's click event to a script that changes something inside the loaded page — and the dynamic text/color change behavior built on top of that.
- This is a team project (multiple collaborators pushing to the same GitHub repo), so part of today's discussion was also about keeping commits incremental so progress stays traceable rather than landing as one large change later.
