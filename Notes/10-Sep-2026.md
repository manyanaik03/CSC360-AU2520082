### 1: Swing Is Built on Top of AWT, Not a Replacement

- Swing does not start from scratch. It reuses AWT's basic tools — event handling, layouts, fonts, colors, and graphics.
- The main difference is who draws the components. AWT components like `Button` and `Frame` use the real buttons and windows from the operating system, so they are called "heavyweight." Swing components like `JButton` and `JFrame` are drawn by Swing itself, so they are called "lightweight."
- Because Swing draws its own components instead of using the OS, it can change its look and feel easily, without changing the app's logic.
- So it's not really AWT vs Swing. AWT is the base, and Swing is a more flexible layer built on top of it.

### 2: What "Abstract" Means in AWT

- AWT stands for Abstract Window Toolkit. "Abstract" means Java gives one simple API, and behind the scenes, the real work is done by the operating system.
- This happens through something called "peers." When you use a Java `Button`, it is actually connected to the real native button of your OS.
- Because of this, the same Java code can run on different operating systems and still look normal, without rewriting it for each OS.
- Common classes like `Frame`, `Button`, `TextField`, and `Graphics` are simple to use, but they are quietly using native OS components underneath.

### 3: Keeping Images Separate From Their Details

- Large images are usually not stored directly inside a database. Instead, the image file is stored in object storage, and only information about the image is stored in the database.
- Object storage (like Amazon S3) is made to handle a large number of files easily and can grow in size without problems. This is better than putting big image files into a database.
- The database instead stores details like the file name, its storage location/URL, size, who uploaded it, when it was uploaded, permissions, and a checksum to check that the file has not changed.
- For private images, signed URLs are used. These give temporary access to a file, so it does not need to be public, and access expires automatically.
- It is still possible to store an image directly in a database as a BLOB. This can work for small files or when strong consistency is required, but for big media apps, keeping the file and the details separate is more common.

### 4: Deciding Where a Web Page Is Built — Server or Browser

- In Server-Side Rendering (SSR), the server creates the full HTML page and sends it ready-made. The browser can show something useful right away, and JavaScript makes it interactive afterward.
- In Client-Side Rendering (CSR), the server sends a simple page along with JavaScript. The browser then uses that JavaScript to build and update the page itself.
- SSR shows content faster at first and is easier for search engines to read, but it needs more work from the server and is harder to cache for pages that are different for every user.
- CSR feels very fast once it is loaded, since moving between pages does not need a full reload. But the first load can be slower, since the browser has to download and run the JavaScript first.
- Neither method is always better, so many modern websites use a mix of both. Also, using SSR or CSR does not automatically make a website accessible — things like proper HTML, keyboard support, labels, and good color contrast still need to be added separately.

### 5: Streaming and Downloading Are Not the Same

- Both streaming and downloading bring data from somewhere else, but the difference is when you can start using that data. Downloading needs the full file first. Streaming lets you start using the data as soon as enough of it has arrived.
- This works because of a buffer. A small amount of data is stored ahead of time, and as long as new data keeps coming in faster than it is being used, playback looks smooth.
- Adaptive bitrate streaming helps when the internet is slow. Instead of forcing one fixed quality, it can switch to a lower-quality version so playback continues without stopping.
- The annoying kind of "buffering" happens when data is being used faster than it is arriving. The buffer becomes empty, and playback has to pause and wait.

### 6: Streaming Is Used in Graphics and Remote Computing Too

- The idea of "not loading everything at once" is also used in graphics. In a large open-world game, not every texture or model is loaded at the start. The game loads what is near the player and removes what is not needed anymore.
- Cloud gaming takes this further. The actual game runs on a remote server, which does the rendering. Only the finished video and audio are sent to your device. Your keyboard, mouse, or controller input is sent back to the server.
- Because the hard work is done remotely, your device does not need to be powerful. But the experience becomes very sensitive to network delays (latency) and unevenness in the connection (jitter).
- Remote desktop and scientific/CAD visualization use a similar idea, where heavy work is done remotely and only the result is shown locally. VR and AR are even more sensitive to delay, since even a small lag can be noticed by the user.

**Q&A Discussed:**

- Q: If AWT already has GUI components, why was Swing created?
  A: AWT components depend on the operating system, which limits flexibility. Swing draws its own components instead, which allows features like changing the look and feel easily.

- Q: Why not store images directly in a database?
  A: Databases are not good at storing large files efficiently. Object storage is made for that, while the database only stores small details about the file.

- Q: If CSR feels faster after loading, why would anyone still use SSR?
  A: SSR shows useful content faster at the start and is easier for search engines to read, which is helpful for public websites, even though it needs more effort from the server.

- Q: Why doesn't streaming need the whole file to be downloaded first?
  A: A buffer stores a small amount of data ahead of time. As long as new data arrives faster than it is used, playback can continue smoothly without waiting for everything.

- Q: Why is cloud gaming so affected by network problems if the server does all the work?
  A: Every action and every video frame has to travel over the network. Even though the device does less work, any delay in the network directly causes lag for the player.
